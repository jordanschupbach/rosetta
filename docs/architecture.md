# Architecture

## Pipeline

```text
C++ header + compiler flags
          |
          v
Clang frontend adapter ---- parse diagnostics
          |
          v
shared declaration model (optional JSON inspection)
          |
          v
backend capability checks ---- unsupported-feature diagnostics
          |
          v
Lua C++ wrapper source + original C++ library
          |
          v
native compiler/linker -> Lua module -> require()
```

Rosetta is implemented in C++17. `src/frontend.cpp` owns Clang invocation and AST interpretation. `include/rosetta/model.hpp` defines target-independent declaration data, with JSON serialization in `src/model.cpp`. `src/lua.cpp` owns Lua capabilities, conversions, exception boundaries, export names, and generated code; `src/lua_runtime.hpp` contains the emitted conversion helpers. `src/cli.cpp` connects them and writes artifacts. These components form the `rosetta_core` CMake target, used by the CLI and C++ tests. Adding a target should reuse the frontend and model, with its own capability validation and emitter.

The R path uses that same frontend, model, policies and compilation context. `src/r.cpp` emits an R `.Call` bridge and a separate R6, S3 or S4 interface selected with `--language r --object-system r6|s3|s4`; R6 remains the default. The native source is identical across all three systems. `src/r_runtime.hpp` supplies scalar/string conversions, exception handling and tagged external-pointer ownership. Native routines are registered with dynamic lookup disabled and invoked through registered symbol addresses. R6 uses active bindings and clone/reinitialization guards. S3 uses classed pointer lists and registered `UseMethod` generics; S4 uses formal classes with an external-pointer slot and `setGeneric`/`setMethod`. The functional interfaces share helpers in `src/r_interfaces.hpp`, with module-qualified class/generic identities. S3 generics use the top-level registry while registered method closures retain their interface environment. S3/S4 assignment shares native storage, and native finalizers provide exactly-once cleanup after all aliases become unreachable. Explicit close invalidates every alias. R errors unwind C++ temporaries through `R_UnwindProtect`; ordinary C++ exceptions are caught inside its callback so R restores its context before an R error is raised. The capability boundaries and loading/build contract are documented in [R and R6](../README.mepml#r-and-r6) and [S3/S4](../README.mepml#s3-and-s4-classes).

`include/rosetta/compilation_database.hpp` and `src/compilation_database.cpp` select parsing context from a [Clang JSON compilation database](https://clang.llvm.org/docs/JSONCompilationDatabase.html). Selection uses the translation unit and/or global record index and rejects ambiguity. The adapter prefers argument arrays, tokenizes literal quoted command strings without a shell, removes common driver actions/output paths and retains semantic options. It rejects launchers, response files and forwarded driver options rather than guessing their meaning. This is a supported subset of GCC/Clang driver arguments, not a universal build-command interpreter. The configured Clang parses the header; the original compiler and source job are never executed.

The process adapter changes directory only in the child before execution, preserving the parent's working directory. Relative compiler paths supplied by the caller are resolved before this change. Model/IR `parse_context` records compiler, directory, effective semantic flags and optional database/source/index provenance; internal AST-driver flags and compiler version are not recorded. CLI override flags follow imported flags. Dependency graph capture, automatic generated-header builds, response-file expansion, modules/PCH and versioned replay manifests remain pending.

Header inspection suppresses Clang's main-file `#pragma once` warning and unused driver-argument warning, allowing inherited `-Werror` with header entry points and toolchain wrappers. Other source diagnostics retain the selected command's settings. The standalone `compilation_database` test parses a real temporary project with relative paths, a forced include and C++20 settings; it also checks quoting, duplicate configurations, overrides, rejected commands, output protection and parent/child directory isolation.

Compiler dependency capture is optional frontend metadata, requested by the CLI's `--depfile` option. The same Clang process emits AST JSON and a private fixed-target `-MD` rule. `src/dependencies.cpp` parses that constrained compiler format, resolves regular-file identity against the parse cwd, and emits escaped/deterministic Make rules. The normalized model carries compiler dependencies without tying them to a backend. The CLI adds policy/context prerequisites and protects all discovered inputs before writing artifacts. `cmake/Rosetta.cmake` owns CMake argument/path handling and consumer compatibility: it probes Ninja depfile escaping and uses a local direct-consumption policy only when required. A real build fixture checks no-op convergence, signature regeneration and newly discovered transitive inputs.

`src/type_spelling.hpp` interprets balanced function/template spellings from Clang's normalized AST types, including nested callback signatures. It is isolated compiler-adapter code, not a replacement parser for C++ source. `src/lua_callbacks.hpp` contains the callback runtime emitted only when selected calls accept callbacks. Both emitted runtimes live in an anonymous C++ namespace to keep module-local type/VM keys from interposing across extension libraries.

`include/rosetta/policy.hpp` and `src/policy.cpp` provide strict versioned, target-independent class selection/lifetime and callback policies. A policy explicitly selects classes, allows method/field subsets, controls constructor exposure, declares borrowed method results whose owner is the receiver, and assigns call-only/retained lifetime to callback parameters. Private/protected members are represented in the model for diagnostics but never accessed by emitted wrappers. The demo's policy is a dependency of its CMake generation step.

The frontend currently invokes `clang++ -Xclang -ast-dump=json` through a POSIX process adapter (`src/process.cpp`) that passes an argument vector directly, without shell interpolation. Temporary files capture both output streams without pipe deadlocks, and temporary directories are released through RAII. Windows needs an equivalent process adapter. JSON parsing uses nlohmann/json with object insertion order preserved: Clang elides filenames relative to previously emitted locations, so reordering keys breaks macro/source provenance. The public declaration model does not expose JSON library types.

This avoids parsing C++ with text heuristics and requires no libclang installation. However, Clang explicitly does not guarantee JSON AST stability between major versions. The model is the isolation boundary; JSON dumps are an adapter input, not our public interface. Return types currently come from Clang's function-type spelling, which is deliberately limited and rejects complex forms. Before broader coverage, use Clang LibTooling or a sufficiently capable libclang adapter for canonical type identities, source provenance, return types, and declaration relationships. Maintain a tested compiler version matrix until then.

The Python path shares the frontend, declaration model, policies and dependency machinery. `src/python.cpp` emits a CPython 3.12+ extension; `src/python_runtime.hpp` supplies strict scalar/string conversions and exception boundaries. The generator itself includes no Python headers or Python implementation dependency. Native objects live in module-associated heap types created by `PyType_FromModuleAndSpec`, with GC traversal of the heap-type reference, a matching type decref during deallocation, explicit close and context-manager slots. Methods and get/set descriptors provide native receiver type checks. Constructor initialization commits ownership only after successful allocation and rejects reinitialization. Visible default arities dispatch to ordinary C++ calls. Multi-phase module initialization creates fresh types for each module; unsupported subinterpreters are rejected and GIL use is explicit. This initial backend preserves full 64-bit integers, UTF-8 text and NULs, but does not expose arbitrary native pointers, callbacks or automatic containers. See [Python](../README.mepml#python) for the public contracts.

The Ruby path also shares the frontend, model, policies and dependency machinery. `src/ruby.cpp` emits an MRI Ruby extension without adding Ruby headers to the generator. `src/ruby_runtime.hpp` supplies strict scalar/byte-string codecs and TypedData owners without stored Ruby references. Each native type has a private descriptor, allocation/finalization callbacks, explicit close, and block-scoped `.open` cleanup through `rb_ensure`. The exception boundary converts protected Ruby nonlocal exits to C++ exceptions, unwinds native temporaries, then resumes the original Ruby exit after leaving C++ catch scopes. Native exceptions follow the same outer boundary. Conversion precedes native receiver lookup to tolerate allocation-triggered Ruby activity. Const methods and property reads respect frozen objects; mutating operations check Ruby's frozen flag. Copying/Marshal/subclassing and colliding module constants are rejected. Native workers never access Ruby, and waits hold the GVL. A compiled runtime probe checks destructor counts across Ruby errors, native errors and nonlocal block exits. See [Ruby](../README.mepml#ruby) for naming, byte encoding and supported scope.

The Octave path reuses the same frontend, model, policies and dependencies. `src/octave.cpp` emits one `DEFMETHOD_DLD` entry point, returning a struct of anonymous dispatcher handles on a no-argument call. Class entries contain constructor/static handles; instance dot indexing and assignment use a private `octave_base_value` representation from `src/octave_runtime.hpp`. Its clones share a native state with unique native storage, so assignment/cell/struct aliases retain ownership and close invalidates all aliases. The state contains no Octave references, avoiding runtime/native reference cycles. Private per-module native types prevent symbol/type collisions. Type registration and module pinning retain callback/destructor code for the interpreter lifetime. Integer inputs distinguish typed signed/unsigned values from bounded whole floating values; results use int64/uint64 transport without conversion through double. Native exceptions receive stable Octave error identifiers while execution/interrupt/exit exceptions propagate. Serialization is rejected, and native workers never call Octave. See [Octave](../README.mepml#octave) for the public contracts, scope cleanup and module lifetime limits.

The Julia backend uses the same frontend, model, policies and dependency machinery. `src/julia.cpp` emits a private C ABI shared-library bridge and a `.jl` module using `ccall`; the generator and bridge need no Julia headers. `src/julia_runtime.hpp` defines tagged fixed-width scalar/string transport, caller-freed copied results, status/error translation and a native registry of typed owners. IDs never expose native addresses, and type checks reject mismatched records. A per-library mutex serializes native operations with close and shutdown. The Julia interface roots string arguments across calls, copies native output bytes inside a `finally` cleanup boundary, and installs finalizers plus explicit close on concrete mutable owner types. Property access and flattened method functions dispatch through the same native boundary. An exit hook cancels and joins remaining native tasks by clearing the registry. No Julia references enter native storage and native workers never enter Julia. See [Julia](../README.mepml#julia) for supported types, ABI lifetime and current limits.

The Common Lisp backend reuses the same C ABI bridge (`src/cabi_runtime.hpp`) and emits a `.lisp` interface over CFFI from `src/common_lisp.cpp`; generation needs no Lisp installation. Each module defines a public package that uses no other package, so upcased C++ names cannot clash with `COMMON-LISP`, and a private `.IMPL` package holding the runtime from `src/common_lisp_runtime.hpp`. Arguments are copied into foreign memory for the duration of a call, and result bytes are copied and freed through the originating library in an `unwind-protect`. Owners are CLOS instances holding a registry ID; `cl:close` methods, a `with-owner` macro and trivial-garbage finalizers release them, and SBCL's exit hook clears the registry. See [Common Lisp](../README.mepml#common-lisp).

The Java backend emits typed Java source and a JNI bridge from the shared model and class policies. `src/java.cpp` lowers scalar signatures to Java primitives, exact unsigned BigInteger values and copied byte arrays, generates trailing-default overloads, and exposes selected records as final AutoCloseable nested classes. Named Java packages participate in JNI name mangling. `src/java_runtime.hpp` owns typed native registry entries, serializes calls/destruction, bounds scalar conversions and manages local JNI references without retaining Java objects or JNIEnv pointers. Pending Java exceptions unwind through a private C++ marker and retain their original identity; translated native exceptions are raised after native temporaries unwind. Constructor publication rolls back native storage if JNI boxing fails. Java Cleaner actions contain only native IDs; reachability fences protect active instance calls and a shutdown hook releases remaining tasks/owners. CMake compiles Java 17 bytecode into a JAR alongside its native libraries and tests the bridge with `-Xcheck:jni`. See [Java](../README.mepml#java) for the typed API, byte-string and lifetime contracts.

## Model evolution

The value-based model contains a header path, functions, namespaces, spelled/canonical types, recursive template arguments and pointer/reference children, function-type results/parameters, cv qualifiers, enum and record declarations, source locations, and diagnostics. Records retain constructor/method/field access levels, static/const/deleted/noexcept flags, definition/destructor/abstractness information and member types. Functions have canonical signature identities, and enum/record types reference their declaration identity. Alias resolution respects the namespace where each alias is defined (including nested class aliases and inline namespace visibility) and recurses through supported qualifiers and type arguments; canonical redeclarations are deduplicated. Dependency enum metadata can validate selected functions without exporting dependency tables. Backend APIs consume the model by const reference. JSON output is for inspection; its schema is not stable yet. This remains an incomplete structured type model: non-type template arguments have spelling nodes, and general layout/base relationships, complex declarators and dependent expressions need richer compiler-derived representation.

Public nested records/enums retain an enclosing `owner` identity; their qualification arrays include enclosing record names as lexical scope components. The Clang adapter keeps internal declaration-context/access maps across forwards and out-of-class definitions, recursively suppressing inaccessible type paths. Qualified member definitions merge with their original declarations after type resolution, preserving original access while collecting defaults. Dependency records contribute public type metadata without entering class selection. Lua reuses its existing flattened export names, class policies, enum codecs and owner-anchored borrowing; lexical nesting alone creates no runtime ownership relationship. Anonymous/template-specific and inherited type lookup remain incomplete.

- Stable declaration IDs, source locations, access and linkage, documentation, attributes, availability, and selection provenance.
- Structured types: builtin, alias, qualified, pointer, lvalue/rvalue reference, array, function, record, enum, template instance, and dependent types. Preserve both identity and spelling; use a type graph to represent recursion.
- Callable records: constructors, methods, static members, operators, cv/ref qualifiers, overload sets, defaults, exception specifications, and calling conventions.
- Record layouts and relationships: fields, bases, virtual members, abstractness, copy/move/destruction traits, and incomplete declarations.
- Explicit binding policies: input/output direction, nullability, encoding, buffer length relationships, lifetime dependencies, owner/borrower transfer, thread affinity, and callback lifetime.

Declaration discovery must remain separate from target support checks. Today some unsupported declarations become frontend diagnostics rather than structured nodes; migrate these into model nodes as their semantics are implemented. Future backends should report capability gaps against the same declarations rather than forcing Lua assumptions into parsing.

Named scoped and unscoped enums are emitted as Lua integer tables. Generated enum argument checks first validate the underlying integer range, then named membership or an explicitly selected flag mask before the enum cast; this avoids invalid casts for enums without a fixed underlying type. The generated C++ compiler evaluates enum constants, including aliases and expressions. Values outside Lua's integer range fail at module initialization. Enum-only modules are supported. Bool-backed enum results are normalized to integer 0/1 consistently with their tables and inputs.

Version-1 `enums` policies name canonical enum identities and positive single-bit basis enumerators. Generation validates references and native static assertions validate basis values and Lua representability. Masks use unsigned underlying bits (with an unsigned-byte transport helper for bool); input checks reject bits outside the basis and admit zero as the empty set. The policy affects parameter validation, preserves raw exported constants/result range behavior, and does not infer flags, change class selection or export dependencies. Native compilation tests verify basis diagnostics with the generated source; exhaustive byte-mask Lua checks and owned-value error/publication tests cover runtime behavior.

The Lua emitter recursively collects enum types from value and callback signatures. Module-local `rosetta_codec<Enum>` specializations share the direct validator and integer publication helper, allowing enum vectors/arrays/optionals/products and copied callback values to compose. Input paths require definitions, including callback results. Native output paths may publish fixed-underlying forward enums without decoding them; their read codec is disabled. Dependency enum codecs do not cause extra tables to be exported. Native results and callback arguments preserve raw values with range checks, while Lua-to-C++ paths enforce named membership or flag policies.

The demo's template examples use ordinary C++ facades to select function, class and parameter-pack instantiations. Rosetta binds those concrete entry points through the normal shared model. There is no target-runtime dependency in the facade and no automatic template instantiation claim. The hierarchy facades similarly hold native shared interface pointers: C++ performs checked casts and virtual-base adjustment, while Lua receives independently owned facade userdata. A selected native virtual override delegates through a retained `std::function`. Interface layouts, RTTI, shared ownership and native identity remain in C++; automatic hierarchy/director generation remains pending. The [Lua feature plan](lua-feature-plan.md) tracks these mechanisms and lifecycle requirements.

## Binding planning and extension contracts

Extended numeric adapters keep compiler-specific integer and floating values in C++ and use explicit decimal transport. They check integer bounds before arithmetic and format finite native long doubles with round-trippable precision. The 128-bit capability has a separately compiled disabled-path test, while Lua digit-cell oracles and native extrema test enabled behavior. General numeric typemaps, arbitrary precision and floating-environment/nonfinite policies remain open.

Unicode adapters in `examples/unicode_library.hpp` use explicit encoding names, copied scalar/code-unit sequences and native UTF/wide string types. They validate before narrowing and keep automatic byte strings independent of Unicode policy. Every scalar is compared against a separate encoder, with malformed-input and intermediate-allocation/publication failure checks. Native `wchar_t` representation is an explicit capability; general encoding typemaps and locale/normalization rules remain pending.

The C++20 generator example owns its coroutine handle, separates resume from value publication and stores terminal exceptions in the promise. The supplied Lua iterator tracks unpublished yields so retries do not resume twice. Frame/body counters, partial-allocation/resume/publication failures and Lua coroutine/VM closure verify cleanup. This native pull protocol is reusable independently of Lua; asynchronous awaitable and executor mapping remain open capabilities.

Ownership-slot adapters in `examples/ownership_library.hpp` make consuming operations explicit between existing facades. Unique moves preserve deleter state; shared promotion reserves its control block before a nonthrowing commit. Weak locking creates a separate shared owner. Aligned placement storage and its custom deleter stay behind native handles, with allocation/destruction counters and ordinary/aligned allocation-failure tests. General consuming typemaps and custom allocator policies remain separate from this reusable native mechanism.

The error example uses a native `Result<T>`/error-data adapter with a selected `IntResult` facade. Typed exceptions, native status/error codes, nested causes and callback failures become inspectable data; captured exceptions can be rethrown through the regular generated boundary. It has no Lua dependency. Private opaque template forward declarations do not request exports; definitions and unsupported public uses remain diagnostic. General exception/result policies and target-language error-object generation remain separate backend capabilities.

Call adapters in `examples/call_library.hpp` and `examples/calls.cpp` select native free/member overloads with exact C++ pointer types, evaluate omitted defaults in C++, select bounded typed C-varargs calls and adapt ref-qualified/constructor APIs. The supplied `examples/demo_calls.lua` chooses among named entry points using explicit Lua type/arity/range rules and reports ambiguity. This preserves reusable native semantics while leaving general overload planning as a separate capability task. Supported non-overloaded declarations now carry trailing-default counts in the shared model/IR. Lua wrappers select an argument-count branch and let C++ evaluate omitted defaults through a direct named call. Borrowed text results publish in that same full expression so default-created temporary storage stays alive through the copy. Exact full-signature calls and strict supplied-argument conversions remain in use.

Advanced native storage is demonstrated in `examples/advanced_values.hpp`: a manually managed tagged union, checked bitfields/packed accessors, a map of variants and a restricted any/tuple store. Concrete facades expose tags and copied values through ordinary supported signatures, keeping lifetime transitions and layouts in C++. These are explicit reusable adapters, not automatic typemaps. Allocation-failure tests verify that preparation/swap-based replacements preserve earlier values and that partial clones release native storage.

The series example uses the same separation for operators: native overloaded operations are exposed through named `IntSeries` methods, and `examples/demo_protocols.lua` wraps generated userdata with Lua arithmetic, comparison, indexing, call, iteration and close protocols. A versioned cursor owns its native storage and checks mutation before using C++ iterators. This is a supplied demo layer; no automatic operator mapping or policy selection is claimed. It leaves the backend's protected userdata metatables intact and gives future backends reusable named operations.

Series division distinguishes native truncating quotient/remainder from floor quotient/modulo. Named C++ adapters implement both conventions without floating-point conversion; the Lua layer maps `/` to the native integer quotient and `//`/`%` to floor operations. All paths guard zero and signed-minimum/-1 before native division. Independent Lua integer-oracle cases, source/cursor preservation, partial native allocation and protected userdata-publication failures test their boundary and lifetime behavior.

The chrono example selects concrete native duration periods behind explicit unit/rounding arguments and stores system/steady time points in a native variant. Scaling and arithmetic are checked before native chrono operations; rounding uses source remainders to handle signed extrema without intermediate overflow. Clock identity is retained by the handle and cross-domain operations are rejected. The facade returns exact integral ticks and actual clock-period metadata; calendar/time-zone and arbitrary-clock mappings remain separate policy work. Existing userdata/default conversion, fault injection, native live counts and VM-shutdown tests apply unchanged to these time handles.

Automatic tuple/pair codecs lower heterogeneous native products to fixed positional tables. The type's arity validates stored keys independently of Lua length, permitting nil optional slots while rejecting metadata/extra indices. Element construction reads left to right with C++ unwinding; fixed arrays share that construction path after dense length validation, including const storage. Pushes run under protected publication and callback bridges. Nested products reuse existing value/enum codecs; reference/handle elements and ambiguous optional layouts remain explicit capability gaps. Empty template instances now have zero model arguments, enabling the empty tuple without a special fake element.

Map/unordered-map codecs share a copied-entry implementation. String maps with non-nil mapped values become raw dictionaries; other shapes use dense fixed-pair lists, preserving optional/monostate keys and values and native typed equality. Ordered keys must be comparable and unordered keys need supported default hashing. Duplicate converted keys are errors; custom policy state is not serialized. Protected per-step dictionary traversal catches errors from invalidated Lua iteration without skipping native node/key/value destruction. Publication checks iterator destructor triviality and runs under the normal protected bridge. Mutation/rehash, enum/tuple/hash keys, borrowed-view GC, callback and allocation-failure tests exercise these paths.

The Lua backend now builds explicit call/class plans before emitting source. Planning resolves class selection, public access, supported signatures, constructor/method collisions and required borrowed-return rules. Constructors, methods, static functions and synthetic field accessors share call generation and conversion/error paths. Evolve this into a shared lowering layer as a second backend arrives: policy interpretation and ownership facts should remain reusable, while runtime-specific capabilities and emission stay in each backend. Typemaps should declare supported source types, target types, conversion failure behavior, cleanup, and lifetime requirements. Validate policies before emitting code.

For Python, Ruby and Lua, direct native extension backends can offer good ergonomics. For Rust, C#, Java, and other C-oriented FFIs, add a reusable C ABI shim with opaque handles, fixed-width boundary types, explicit destroy functions, pointer/length buffers, and status/error accessors. Never expose C++ mangled symbols or STL layout as a portable ABI. Share lowering and ownership rules across these paths; keep target runtime APIs in their emitters. A single mandatory C shim is unnecessary for targets already able to compile native C++ adapters.

Generated symbols should eventually use stable collision-resistant identities, explicit export visibility, ABI versioning, and configurable user-facing names. Output should include a manifest of emitted, adapted, and omitted declarations with reasons. Avoid silent omissions as the default.

## Errors and lifetime

Lua's C API commonly reports errors through `longjmp`. Generated code must not leave C++ objects needing destruction alive across potentially failing Lua API calls. Wrappers reserve a small stack area before constructing native values. Argument codecs use strict type checks and non-throwing raw Lua reads; conversion failures throw C++ exceptions. Native strings and containers therefore clean up normally even if a later argument fails or the library throws. Raw sequence reads bypass metamethods, restore the stack on a C++ exception, and use non-throwing `lua_checkstack` for nested values.

Result publication runs in a type-specific C thunk under `lua_pcall`. This thunk borrows the native result by pointer and owns no C++ objects. Allocating a Lua string/table, or reporting result integer overflow, may jump inside the thunk; the protected call catches it before it can cross native strings or containers. The publisher copies the Lua error into a bounded C++ exception, restores the stack, and throws. After native temporaries and exception scopes exit, the outer wrapper raises the final Lua error using a fixed character buffer. New output codecs must preserve the no-owned-values invariant inside their Lua thunk; new input codecs must avoid allocating/error-raising Lua calls or protect them explicitly.

Value codecs currently cover scalar values, C strings, binary standard strings/views, dense vector/array copies, optional values, fixed tuple/pair products and copied map/unordered-map entries. Mutable scalar/value references, rvalue-reference arguments, ambiguous nil-containing containers, custom allocators/traits and ownership-bearing product elements are rejected by capability validation. Const-reference value arguments refer to temporary copied values for the duration of the call; views borrow Lua storage for that duration. Library code must not retain either. Selected-class references and callbacks use the lifetime rules below.

Borrowed text input wrappers create a view scope. View reads acquire protected registry references to their source strings, including strings inside containers, and scope destruction releases all references after publication or failure. This keeps reentrant callback mutation/GC from invalidating decoded views. A module-local thread-local scope chain restores enclosing calls; the active scope checks the Lua state before accepting a view read. Owned-string reads avoid unnecessary pins. Allocation sweeps inspect both C++ balances and surviving registry roots, including fresh VM registry growth; reentrant tuple/vector tests collect the original Lua fields before native reads resume.

## Class handle ownership

Selected classes use full Lua userdata containing a trivial header: a module-local type tag, native pointer, ownership state/deleter, optional parent header, readonly flag, and shared-ownership discriminator. Native objects are heap allocated, so Lua userdata alignment does not constrain the C++ type. Type tags and userdata-size checks prevent unrelated userdata from being interpreted as a class. Generated type-trait assertions require public nonthrowing destruction. Ordinary Lua metatable access is protected.

Class metatables are registered before any constructors can run. Creating a handle allocates and initializes the empty userdata, installs its finalizer, and anchors any parent inside a protected Lua call. Only after this succeeds does the wrapper construct a native object, release a unique pointer into the handle, or allocate a shared-pointer holder. A C++ allocation/constructor failure leaves an inert finalized header; a Lua allocation failure leaves ownership with native RAII values. Every ownership commit after native construction is non-throwing. By-value class results move/copy into an owned allocation; nonrelocatable results require an owning-pointer factory instead. Copying native arguments checks the C++ copy-construction trait, while consuming moves remain a future policy.

`borrow_self` results retain the actual Lua receiver in a user-value slot and store a parent-header link. Access checks the complete chain before touching native storage. Explicit close clears the pointer before destruction, invalidating children immediately; closing a borrowed header never deletes its native target. Closing an intermediate borrow invalidates descendants too. Once a handle is closed, access fails before following any parent pointer that may have become unreachable. A policy must guarantee the borrowed address remains stable while its owner is open; arbitrary native replacement/reallocation is not inferred.

`close`, `__close`, and `__gc` share an idempotent native release operation. Generated RAII pins increment active-call counts on receivers, selected-class arguments and their complete owner chains. Explicit close rejects active handles; the finalizer skips active ones (which normal GC cannot reach while pinned arguments remain rooted). This prevents callback reentrancy from freeing native storage still in use. Pins unwind on all C++ error paths. Shared handles own separate shared-pointer holders, so one close can leave another owner alive; borrows attached to the closed handle still expire. Readonly flags propagate through borrow chains and reject mutating methods/fields/arguments. Nullable raw class pointers and shared pointers accept nil; raw borrowed/owned handles cannot be promoted implicitly into shared ownership. Module-level type unification, inheritance casts and weak/custom ownership remain future work.

## Callback bridge

Policies identify callback parameters by qualified callable name and one-based C++ position, independent of any Lua receiver argument. Selected `std::function<R(Args...)>` inputs receive a generated bridge over supported value codecs; native reference/view results and unsupported class/function values are rejected. Native `noexcept` callables accepting callbacks require an explicit error-status facade rather than allowing a Lua error to terminate C++.

Callback state holds the originating Lua coroutine and function through registry references, a shared VM lifetime token, and an atomic validity flag. A call-only scope invalidates callbacks and releases references at wrapper exit even if native code kept an illicit copy. Retained copies release their references when native ownership ends. Nil represents an empty native function. Copies capture shared state locally during invocation; the native library must also keep its callable object alive while executing it, as the demo event source does with a snapshot for self-unregistration.

Invocation checks the fixed VM owner thread, VM liveness and callback validity before touching Lua. Callback argument publication and Lua execution run in a protected C thunk with no owned C++ values. Return conversion happens after the protected call and restores the Lua stack on success or exceptions. Lua errors, forbidden yields and invalid returns become bounded C++ exceptions; the outer native wrapper catches them after cleanup. Native C++ can catch them intentionally. The C-style demo catches failures in a nonthrowing pointer/context trampoline, records an exception/status, and rethrows after returning through the native operation.

Last-copy destruction off-thread enqueues callback state in a mutex-protected intrusive list without allocating or calling Lua. Binding entry/exit and callback invocation drain that list on the owner thread. Reference release uses nonthrowing stack reservation and defers cleanup if space is unavailable; no destructor longjmp is permitted. No VM mutex is held while stack growth or Lua reference cleanup might run. A registry-rooted VM token marks the VM dead and drains pending state during finalization; surviving native copies then reject calls and delete only C++ state. Callers must serialize Lua access, keep the generated library code loaded until its callbacks are gone, and avoid throwing Lua callbacks in native destructors.

Registry retention can create self-capturing owner cycles. The documented retained policy requires explicit unregister/close to break those cycles; GC-only cycle detection is not implemented. The native task adapter in `examples/async_task.hpp` publishes C++ promise/shared-future completion and invokes retained callbacks only through explicit owner-thread dispatch. Worker cancellation and join belong to task ownership. Workers never use Lua; task destructors release handlers without executing Lua callbacks. General schedulers, arbitrary cross-thread Lua execution, direct C trampoline generation, callback class values and automatic virtual override directors remain future work. The detailed [callback rules](lua-feature-plan.md#callback-policies-and-lifetime-rules) and [async task contract](lua-feature-plan.md#async-task-adapter) distinguish these limits from implemented behavior.

Every new pointer/object mapping must specify who destroys it, when borrowers expire, whether null is legal, and which thread can use it. No general ownership inference from raw C++ signatures is reliable. Offer safe defaults and explicit configuration; reject unresolved policies. Future userdata must distinguish owned and borrowed handles, handle manual-close plus GC safely, retain required owners, and prevent use after destruction.

## Validation

Buffer facades encapsulate native storage/generation updates and use weak, generation-checked views before acquiring ephemeral spans or pointers. Explicit directional adapters adopt array outputs into RAII before copying them across the boundary. Tests cover structural invalidation, shared ownership versus weak expiry, empty/binary ranges, failed growth preserving views and output-copy/publication failures releasing native arrays.

Compile-time/template examples use a C++20 native implementation with concrete facades; CMake parses and compiles the demo with matching C++20 settings. The generator/core remain C++17. Lua tests exercise selected instantiations and compiler fixtures verify invalid concept/SFINAE uses and nonconstant arguments to immediate functions. Direct consteval bindings receive an actionable facade diagnostic.

Advanced-value and async scripts run both as native modules and inside the allocation-counting host. The host sweeps partial task construction, record cloning, map insertion and any/tuple replacement failures; it also checks value preservation, Lua publication failures, wrong-thread task dispatch and shutdown with nontrivial storage and pending workers alive.

CMake builds `rosetta_tests` from `tests/test_generator.cpp` with a small exception-based test harness; failed checks remain active in Release builds. CTest runs the C++ suite, CLI help smoke test, independent scalar module, Lua integration, object/callback/hierarchy lifecycle and REPL startup scripts, and an embedded-VM native cleanup test. The latter counts ordinary C++ allocations independently from Lua, sweeps partial callback registration failures, injects Lua/native failures at callback argument/body/result boundaries and hierarchy factory/cast publication, runs ownership/callback/hierarchy scripts, and verifies native copies after VM shutdown. Native destructor/live counts cover owner/borrow/shared lifetime transitions; the embedded executable also permits ASan/UBSan checks without loading an instrumented module into an uninstrumented interpreter. CMake custom commands track the generator, example header and policy, so changes regenerate and recompile bindings automatically. The justfile provides configure/build/test/demo/run/clean recipes over CMake and CTest. JSON is an explicit system dependency; configuration never downloads packages.

Use real compiler fixtures for declaration extraction and capability diagnostics. Compile generated source and execute each target language's native loader for behavioral coverage. Test conversion boundaries and failure recovery, not merely generated text. Add destructor counters and sanitizers with ownership support, multi-module tests with shared types, and callback reentrancy tests when those features arrive. Generated-source snapshots may help diagnose changes but cannot substitute for runtime tests.

Variant codecs select alternatives by explicit one-based tags and construct with `std::in_place_index`, preserving duplicate native types. Input validation scans raw keys before decoding the selected payload, avoiding Lua field-name allocation across earlier owned native arguments. Payload decoding occurs after traversal ends, so reentrant GC cannot invalidate a later iteration key. Output codecs borrow `std::get<I>` values under the existing protected publisher; they create no owning visitor temporaries across Lua allocation/error calls. Valueless native variants raise a protected publication error. Monostate extends the shared nil-capability rule used to reject ambiguous sequence/optional shapes and select map entry-list representation.

The filesystem facade keeps native path/metadata operations behind an owned temporary workspace. File writes stage a sibling before rename; directory snapshots cross the boundary as copied vectors, with no live iterator handles. POSIX resource guards keep traversal and cleanup catchable under C++ allocation exhaustion, avoiding the installed standard library's allocating noexcept iterator internals. Last-owner cleanup traverses descriptors without following links or allocating C++ storage. Native allocation counts, Linux descriptor counts, filesystem content assertions and shutdown tests verify the resource boundary. Encoding, allowed-root, path-component and external-mutation assumptions belong to this explicit adapter rather than Lua-specific model nodes.

Linear sequence codecs share dense-table validation and protected publication across deque/list/forward-list, preserving order with forward insertion when needed. Set codecs share element conversion and distinguish unique/multi insertion; nil-capable element types acquire a one-slot product box. Map codecs use a multiple-key parameter that forces multimaps to entry lists. Backend capability checks validate default ordering/hash requirements recursively, excluding unordered associative values from ordered keys. The shared model continues to carry ordinary recursive C++ types without Lua-specific container nodes. Publication borrows elements with trivial native iterators; input unwinding releases partial blocks/nodes/buckets and call-scoped string pins.

Name resolution indexes Clang namespace/alias/type/function declaration IDs internally but emits only canonical identities. Namespace and type-prefix aliases bind the nearest first qualifier before expansion; template argument lookup keeps the original lexical context even when the primary starts at global scope. Explicit using shadows import type identity and visible callable overloads without creating exports. Namespace function types resolve at declaration time, record subtrees resolve on completion of the enclosing class, and out-of-class members resolve before merging. This separates type lookup timing from default-call validation against the completed header. Dependency record names can identify nested enum/alias paths without selecting dependency classes. Using-directive/inherited/dependent lookup and cross-module registration remain broader semantic work.

Explicit class-template using imports retain the native template primary in the frontend and preserve lexical argument lookup; supported standard instances reuse the existing codecs. Native container-adaptor examples separately select stack/queue/min/max-priority instantiations behind a Worklist facade. Copied native snapshots drain outside Lua publication, keeping container ownership out of protected thunks. Shared handles preserve one mutable state; clones copy it independently. Pop copies before native consumption, while later publication failure does not roll back consumption. Allocation accounting and mode-by-mode fault sweeps verify preparation, publication and shutdown cleanup.

The synchronization facade encapsulates atomic counter operations and separately mutex-guarded volatile storage; it exports native limit/width metadata rather than assuming host integer widths. Checked compare/exchange loops avoid overflow before arithmetic. Joined worker groups retain result/error/stop storage until every started thread exits, even if a later launch fails. Workers collect C++ values and exception_ptr only; Lua publication occurs after joining under the existing protected boundary. Per-thread native TLS remains distinct from VM/coroutine identity. Partial native effects survive worker or publication failure, while state, capture and exception lifetimes have allocation accounting and shutdown checks.

Typed member-pointer facades select native data/member-function pointer alternatives in a C++ variant and apply them with std::invoke. Base-to-derived member-pointer conversion and virtual dispatch stay under the compiler's ABI rules. Enum descriptors select supported values; raw bytes/addresses never become wire representations. Const target references reuse existing readonly validation, mutable operations require mutable handles, and target/selector owner chains are pinned normally. Selector copies hold independent native pointer values while target sharing remains explicit. Type/arithmetic/input-allocation failures precede writes; copied text results publish through the existing protected bridge.

The native ABI fixture isolates compiler/runtime settings at a separately compiled object target. Its versioned C interface contains fixed-width scalars, byte ranges, status codes, opaque handles and nonthrowing allocator/callback functions. The generated Lua bridge retains exceptions/RTTI and invokes a typed facade. That facade captures callback exceptions before returning a failure status to native code and rethrows only after the disabled-exception library returns. Both static and shared linkage exercise identical source, with a dynamic-loader visibility test and independent C11 header compilation. This is a reusable boundary pattern rather than generated universal C-shim support; ABI generation and other backends remain separate milestones.

Module/PCH adapters separate semantic API discovery from native artifact management. Rosetta parses the ordinary facade header; a native implementation imports a C++20 named module, exported partition and header unit. The example-specific Clang build graph makes BMI dependencies and linkable module objects explicit and propagates native global/build/sanitizer options into configuration-specific artifact directories. A separate CMake-managed PCH target exposes the same ordinary-signature pattern. These features add no Lua-specific type nodes and do not imply arbitrary BMI/PCH AST replay support. Real native rebuild tests and runtime allocation/error checks verify the facade and build boundary.

Native declaration/storage facades keep immovable objects behind shared opaque state and expose identity comparisons rather than addresses. Const native access can update explicitly mutable bookkeeping; publication failure therefore does not imply rollback. Local/unnamed/anonymous-namespace types are adapted in their defining translation unit. Multidimensional C array and restrict examples copy into distinct fixed native buffers before invoking the native operation; shape validation belongs to the shared nested-array codec, while the facade owns the no-alias and error-preservation contract. These mechanisms do not add assumptions about native layout to the model.

Returned callable facades own shared slots containing native std::function results. A copy duplicates the function target according to its native copy semantics; a shared facade retains the same slot. Invocation retains a shared pointer to the active function object, preserving mutable capture state and allowing reentrant clear without destroying the executing callable. Native result preparation precedes capture/target mutation, while later target-language publication failure does not roll back that native effect. Retained Lua callbacks reuse the existing VM lifetime/registry bridge, and bound member targets retain their native shared owners. The optional Lua __call/__close layer delegates to these ordinary handle methods.

The class-value callback example adapts an actual native Record(Record) function through a synchronous C++ invocation frame and a call-only void notification. Each native invocation owns copied input/optional output values, with a stack-scoped guard restoring the previous invocation after recursion or errors. Result replacement copies first and moves only after preparation succeeds. Facade argument/result methods transport owned copied class handles through existing generated policies. The supplied Lua protocol closes its temporary argument after copying the callback's selected result; explicitly copied handles remain independently owned. This keeps class-value transport out of Lua-specific model nodes while direct class-valued callback generation remains future work.

The cooperative executor example owns coroutine handles in shared native task controls and stores weak controls in its FIFO ready queue. A custom awaiter reposts suspended work; dispatch retains one strong control while resuming, rejects recursive dispatch and destroys a completed frame before releasing the control. Promise result/exception storage outlives frame destruction, so completed task handles need not retain callback registry roots. Suspended cancellation destroys the frame; close during a callback is safe because dispatch retains the running control until suspension/completion. Owner-thread checks precede task/queue access. Lua callbacks execute only inside explicit pumping on that thread and use the existing protected bridge. This is a concrete native awaiter/executor contract rather than generic awaitable code generation.

The two-module interoperability example preserves each generated module's private userdata tags and moves native identity through an explicit shared-library registry. Versioned string tickets resolve weak native records; successful import creates a new facade with shared ownership of the same opaque C++ state. Last-owner destruction unregisters the identity. The registry never owns a Lua reference or keeps native objects alive merely because a ticket string exists. Mutable-only export/share methods preserve readonly handle restrictions. Native mutexes guard registry/data access, and copied outputs publish after locks have unwound. Both generated modules link the same native library; direct foreign userdata remains rejected. This mechanism also permits explicit exchange between separate Lua VMs without sharing Lua objects or stacks.

The C# backend emits a typed static API and a private C ABI library. Its native scalar/owner runtime is shared with Julia; neither backend needs target runtime headers for native generation. Sequential blittable structs carry fixed-width scalar tags and pointer-sized byte lengths. Generated P/Invoke methods pin input byte arrays and copy/free returned bytes in finally blocks. Owners use SafeHandle with a separate full-width registry ID and a sentinel handle, preserving every ID bit independently of pointer width. DangerousAddRef/DangerousRelease retain an owner during each call; the native registry mutex serializes calls and destruction. Constructors allocate their SafeHandle before creating the native owner and transfer the returned ID before managed boxing/allocation. Native exceptions become managed exceptions after the boundary. An exit hook releases remaining owners, including cancellation/join of pending native workers.

C# example projects target .NET 10 and build from SDK framework packs with NuGet sources cleared. CMake tracks generated C++ and C# artifacts; runtime tests cover signed/unsigned limits, byte preservation, failure recovery, mutable/readonly properties, alias disposal, finalization, concurrent disposal and native facade/async behavior. The README runner compiles top-level C# chunks with generated APIs inside a dedicated Nix shell.


The Fortran backend emits a Fortran 2018 module with `bind(c)` interfaces over the shared private C ABI. A small boundary adapter uses signed fixed-width fields and pointer-sized lengths with matching `ISO_C_BINDING` kinds, and converts them to the shared runtime's tagged values. Character arguments retain their length and remain addressable during calls; results are copied before native bytes are freed. Integer transport uses signed 64-bit Fortran values and checks narrower native widths, unsigned signs and unsigned output representability. Optional arguments select contiguous native default arities. An optional `rosetta_error` status preserves native error codes/messages; calls without status use `error stop` after native result cleanup. The implementation follows the GNU documentation for [interoperable procedures](https://gcc.gnu.org/onlinedocs/gfortran/Interoperable-Subroutines-and-Functions.html) and [ISO_C_BINDING](https://gcc.gnu.org/onlinedocs/gfortran/ISO_005fC_005fBINDING.html).

Fortran derived types store private registry IDs and require explicit close. Intrinsic assignment shares an ID; closing either alias erases the owner and all subsequent native receiver lookups fail safely. No implicit finalizer closes copied IDs. Initialization publishes a new owner only after native construction succeeds and closes the previous receiver owner on successful replacement. Native registry destruction releases remaining owners at normal process exit, and an explicit module shutdown is available. Calls and destruction share the native mutex. Fortran name validation accounts for case-insensitive collisions, generated field accessor names, runtime imports and the standard 63-character limit. CMake compiles module sources before consumers and exposes its compiler-specific module directory; the runnable README runner compiles complete Fortran programs against the generated modules.

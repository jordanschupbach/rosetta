# Lua demonstration coverage audit

The Lua feature-family demonstration goal is complete. This audit checks all 21 families in [the roadmap](roadmap.md#c-feature-inventory) against native implementations, executable Lua behavior and failure/lifetime evidence. The [coverage plan](lua-feature-plan.md) retains the automatic/facade/protocol/policy contracts and their limits. Completion covers the requested documented and executable mechanisms; universal automatic support, every feature combination, additional backends and foreign platform validation remain product work.

## Additional mechanisms verified

1. **Implemented:** returned native callable objects as owned, invocable handles. `callable_library.hpp` returns captured/bound/pointer/empty native functions, [test_callables.lua](../tests/test_callables.lua) exercises copy/share/error/close behavior, and the embedded host covers allocation failures and shutdown. General direct function-result generation remains broader work.
2. **Implemented:** native class-value callback arguments/results through a synchronous frame adapter. `class_callback_library.hpp` invokes `std::function<Record(Record)>`; [test_class_callbacks.lua](../tests/test_class_callbacks.lua) checks copied ownership, temporary expiry/explicit retention, recursion, errors and readonly/close rules. The embedded host tests strong-copy/nesting restoration, allocation faults and shutdown. General automatic/borrowed/consuming class-value policies remain broader work.
3. **Implemented:** a custom native co_await operation and owner-thread FIFO executor. `executor_library.hpp` implements weak scheduling, suspended cancellation, shared task ownership, stored errors and frame destruction. [test_awaitables.lua](../tests/test_awaitables.lua) and the embedded host cover lifecycle/reentrancy/callback failures, wrong-thread rejection, allocation exhaustion/publication faults and shutdown. Arbitrary awaiter discovery and concurrent/I/O scheduler integration remain broader work.
4. **Implemented:** independently generated modules exchange shared native object identity through versioned weak-registry tickets in a common native library. [test_interop.lua](../tests/test_interop.lua) exercises both loading orders, accepted tickets/rejected foreign handles, readonly rules, identity/mutation, independent close/GC and module reload. The embedded host adds independent-VM ownership, native/Lua creation/import/publication faults and shutdown. General automatic shared userdata ABI/type registration remains broader work.
5. **Verified:** the final audit covers all 21 inventory families, the eight plan gates, the seven REPL protocol helpers and the implementation/test separation below. Stale summary notes were reconciled against the actual adapters. No required Lua demo mechanism remains open. Automatic-generation breadth and additional backend/platform delivery retain explicit product tasks below.

## Validation

Audit date: 2026-10-19. The current executable source/policy/build files were checked against the normal and sanitizer test-log timestamps; no executable inputs changed after those passing runs. Documentation changes reconcile the audit and plan rather than changing runtime behavior.

- **49/49 CTests pass** on the configured Linux/Clang 19/Lua 5.4 build with warnings treated as errors. The generator test contains **53 passing compiler/model/generation fixtures**. The full CTest evidence is preserved in `build/coverage-test.log` and `build/Testing/Temporary/LastTest.log`.
- **ASan/UBSan embedded cleanup passes** with all **34 feature scripts**, including native/Lua allocation failures, destructor/resource counts, native copies after VM shutdown, independent VMs and all recent adapters. LeakSanitizer scanning is disabled because this sandbox disallows its process tracing; ordinary/aligned native allocation balances and native resource/frame/registry checks remain explicit tests. The embedded check covers the latest linked native code and the explicitly asserted resource balances.
- **`just concurrency-tsan` passes**, compiling/running the independent native contention, TLS, volatile-storage and worker-error helper with ThreadSanitizer.
- **CMake `lua-repl` passes interactive assertions**, including callable, cooperative executor and cross-module helpers, and closes the runtime cleanly.
- **Nix environment validation limit:** `flake.nix` parses and declares Clang, CMake, Ninja, just, JSON and Lua 5.4 in both shells; `just lua-repl` invokes that shell before the private CMake recipe. Executing the Nix wrapper in this sandbox fails at the daemon socket with `Operation not permitted`, before entering the shell. The underlying CMake/native REPL path is verified. Entering the declared shell must be validated on a machine permitted to use its Nix store/daemon; no claim of successful sandbox Nix entry is made.

The family table and acceptance rows are source/runtime traceability, not a claim of exhaustive code-path, ABI or feature-combination coverage. Reproduce normal validation with `just test`, inspect the demo with `just demo`, and use `just lua-repl` on a Nix-capable host. Build the embedded host with ASan/UBSan to reproduce the allocator/frame checks without loading an instrumented module into an uninstrumented Lua process.

## Remaining product work

These tasks were already broader work in the plan and remain in the roadmap; closing this demonstration does not mark them implemented:

- Extend semantic extraction and automatic planning: using-directive/inherited/dependent lookup, complex declarators, generic overload ranking, selection/rename/instantiation manifests, constants/reflection evaluation and module/PCH replay. The current supported surfaces use exact native declarations or explicitly selected facades.
- Generalize codecs/policies: custom template allocators/traits, ownership-bearing container elements, borrowed/consuming class callbacks, raw function-pointer/result generation, automatic directors/operators/hierarchies, arbitrary owner invalidation and shared userdata ABI/type registration. Existing explicit adapters define executable contracts rather than inferring missing lifetime facts.
- Expand runtime/platform capabilities: additional awaiters, I/O/event-loop/concurrent readiness integration, nonfinite/payload numeric policies, additional filesystem policies, foreign calling conventions, Windows/macOS/cross-target validation and compiler/standard-library matrices. Current target limitations and capability checks remain documented per adapter.
- Deliver broader tooling and languages: richer source/target documentation and maps, replay/plugin manifests, Meson/package integrations, automatic reusable C-shim generation and additional native FFI backends. Only the Lua 5.4 backend is delivered here. C++23/future standard-library/reflection support depends on concrete toolchain capabilities; the supported C++17/core and C++20/demo toolchain does not provide native reflection.
